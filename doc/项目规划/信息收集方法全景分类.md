# 维度一：按采集手段分（7 大类）

**这是最关键的一层分类，因为它直接决定：技术实现难度、是否需要授权、法律风险等级。**

## 零、先分清三种"主动/被动"的基本形态

| 形态 | 定义 | 能否拿到"现在"的真实状态 | 目标侧是否留下痕迹 |
|---|---|---|---|
| **主动探测** | 你自己向目标发包 | ✅ 能 | ✅ 留下（防火墙日志/IDS 告警/WAF 日志/established 记录） |
| **被动索引** | 查别人已经扫好的公开索引 | ❌ 必然滞后（结构性） | ✅ 平台方留下，你不留 |
| **公开检索** | 搜索引擎/公开数据集里找 | ❌ 只反映被索引过的内容 | ❌ 完全不留 |

> ⭐ **关键认知**：被动索引的"滞后"是**结构性的，不是工具问题**。网上流传的"Shodan 76 小时发现新服务 / Censys 12 小时"无法独立验证，但**"现在是否还开着"这个问题，被动索引永远答不了** —— 只能主动。

---

## A 类：主动探测（Active Probing）⚠️ 需授权

**你主动向目标发包，拿到"此刻"的真实状态。**

| 手段 | 干什么 | 技术要点 | 典型工具 |
|---|---|---|---|
| A1 主机发现 | 目标机是否在线 | ⚠️ 云上安全组 DROP ICMP 会导致误判为 down，**必须加 `-Pn`** | nmap, ZMap |
| A2 端口扫描 | 哪些端口开 | SYN 半开 vs 全连接；**SYN Proxy 会造成大规模误报** | naabu, masscan, ZMap |
| A3 服务指纹识别 | 端口上跑的是什么、什么版本 | 必须发协议握手拿 banner；指纹库匹配 | httpx, tlsx |
| A4 TLS 证书层 | 证书链、SAN、有效期、JARM 指纹 | JARM 是主动的：10 个构造 ClientHello → 62 字符指纹 | tlsx, openssl |
| A5 Web 探测 | 状态码、标题、跳转链、响应头 | 需显式开 favicon/JARM（默认关闭） | httpx, katana |
| A6 爬虫 | 站内全量 URL | 深度/广度、JS 动态路由 | katana, gospider |
| A7 敏感文件探测 | `.git/`、`.env`、备份文件 | 字典 + 状态码判定 | ffuf, nuclei |
| A8 漏洞验证 | 已知漏洞是否可利用 | ⚠️ **跨出"信息收集"，进入"安全测试"** | nuclei |
| A9 协议层枚举 | SMTP RCPT TO / DNS zone transfer | ⛔ **报告明确禁止 SMTP 枚举**，法律风险收益比极差 | — |

**A 类核心边界（报告原文）**：

> **云上扫到的不是"主机开了什么"，是"安全组允许公网访问什么"。**
> 要回答"这台机器实际开了什么"，唯一权威方法是登录主机执行 `ss -lunp`。

**A 类合规等级：🔴 高**
- 董某案：租赁境外虚拟主机远程运行扫描软件，**多次对县政府信息网站扫描（被防火墙拦截）** → 非法侵入计算机信息系统罪，有期徒刑 9 个月。**扫描本身即被认定为"侵入"的实施行为，即使未成功**
- 《刑法》285 条 2 款门槛低得惊人：非法控制计算机信息系统 **20 台**以上、获取其他身份认证信息 **500 组**以上即入刑
- ⚠️ **一次 `naabu -p-` 对一个 /16 打全端口，就可能越过"20 台"这条线**

## B 类：被动索引查询（Passive Index）✅ 低风险

**查别人已经扫好的公开索引，不向目标发包。**

| 手段 | 数据来源 | 特点 | 工具/平台 |
|---|---|---|---|
| B1 全网端口索引 | Shodan / Censys / FOFA / ZoomEye / Quake / Netlas / LeakIX | 结果集差异巨大，**失败模式完全不同** | uncover（多引擎聚合） |
| B2 证书透明度日志 | Google CT / crt.sh / CertSpotter | **双向的** —— 你能查到别人，别人也能查到你 | crt.sh |
| B3 被动 DNS | SecurityTrails / RapidDNS / dnsdumpster | 历史解析记录，**含已失效资产** | SecurityTrails |
| B4 历史 URL 归档 | Wayback / Common Crawl / OTX / URLScan | 挖已下线端点 | gau, waybackurls |
| B5 云厂商 IP 段清单 | AWS/GCP/Azure/阿里云官方公布 | ⭐ **云上 ASNs 归属必须先查这个** | 各云厂商 IP 段 JSON |
| B6 公开代码仓库 | GitHub / grep.app / Gitee | 搜内部函数名、密钥、配置泄露 | grep.app |

**B 类的三个硬结论**：

1. ⭐ **最省钱的实践建议：至少用两个引擎，取 diff**。新出现的资产往往就是配置最粗糙的那批 —— 这是免费获得高价值线索的最便宜方式
2. ⭐ **FOFA 在国内资产测绘上强于 Shodan/Censys**，原因是**境内扫描节点 + 中国特色指纹库**（35 万+ 指纹，13 大类 130+ 子类，大量国产 OA/中间件/小众 CMS/政务金融系统）
3. ⚠️ **国内可用性是决定性因素**：FOFA/ZoomEye/Quake/Hunter 直连快；**Shodan 需代理**；Censys 慢且部分时段超时

**B 类合规等级：🟢 低**（但见下）
- 在 FOFA 上检索已收录的 banner = 检索公开索引，通常不违法
- ⚠️ **但 FOFA 免费/个人/专业版均不可商用** —— 免费层仅非商业
- ⚠️ **Censys 免费层只 250 查询/月**；LeakIX 免费层结果延迟 15-30 天，对应急响应致命

## C 类：公开检索（Open Source Retrieval）✅ 零风险

**搜索引擎 + 公开数据集，纯粹"查已有的网页"。**

| 手段 | 干什么 | 关键技巧 |
|---|---|---|
| C1 Google Dork | 借搜索引擎索引找隐藏资产 | ⚠️ **2026 已废弃算子**：`cache:`(2024初) `link:`(2017) `related:`(2023) `info:`(~2019) `daterange:`/`~`(2013) `+`(2011) |
| C2 站内检索 | `site:xxx filetype:sql` | ⚠️ **冒号与其值必须紧贴** —— `site: nytimes.com` 解析失败，**这是最常见的静默失败** |
| C3 社交媒体 | LinkedIn / 微博 / 公众号 / X | ⛔ 人员情报，见 C 类红线 |
| C4 代码搜索 | GitHub / grep.app / Gitee | 搜函数名、内网域名、密钥 |
| C5 招聘 JD | 推断企业技术栈 | 从 JD 里招"OA 用什么"推断中间件 |
| C6 公开文档 | 泄露的 PDF/Word/配置文档 | `filetype:` 语法（⚠️ Baidu 支持不稳定） |

**2026 可靠工作的算子**：
```
布尔层   "精确短语"  -排除  OR(必须大写)  *通配  ()分组  AROUND(N)(必须大写)
位置层   site:  intitle:  allintitle:  inurl:  intext:
类型层   filetype: / ext:
日期层   before: / after: / 数值区间 ..（点号两侧不能有空格）
实用技巧 udm=14 强制经典结果视图、剥离 AI Overviews
```

**C 类合规等级：🟢 零**（纯被动检索）
- ⚠️ 但**用无痕窗口或登出 Google** 做客观调研 —— 登录态会污染 SERP

## D 类：注册与备案信息（Registry / Whois）✅ 零风险

**域名的"身份证信息"，查公开注册数据。**

| 手段 | 数据源 | 拿到什么 |
|---|---|---|
| D1 WHOIS / RDAP | 43 号端口、IANA RDAP | 注册商 / 注册人 / 创建时间 / 过期时间 / NS |
| D2 ICP 备案 | 工信部 + 各省局 | ⭐ **国内资产必备**，海外平台完全没有这层数据 |
| D3 工商数据 | 天眼查 / 企查查 / GSXT | 股权结构 / UBO / 年报 / 裁判文书 |
| D4 历史 WHOIS | SecurityTrails / WhoisXMLAPI | ⭐ **域名历史归属人** —— 品牌并购、域名抢注调查的关键 |

**⚠️ 工商数据的免费层陷阱**：
- 天眼查/企查查免费层只有：企业名称、统一社会信用代码、法定代表人、注册资本、地址、经营范围、第一层股东、诉讼/专利/商标 tease 计数
- **付费才有**：完整股东链与实际受益人（UBO）、**年报（含员工数、营收、社保）**、完整裁判文书、行政处罚、历史变更
- **结论：只用免费层无法 meaningfully 完成任何一次供应商核实**
- 判例警示：杭州中院 (2020)浙01民终4847号 —— 从 GSXT 爬取企业数据做商业报告，因发布某金融集团"清算信息"有误致商誉受损，**认定构成商业诋损 / 不正当竞争**

**D 类合规等级：🟢 零**（但爬取后**再分发**可能构成不正当竞争）

## E 类：第三方数据聚合（Third-party Data）🟡 中风险

**花钱买别人的情报。溢价买的是"时间差"，不是"数据量"。**

| 手段 | 代表 | 你实际买到的 | 价格量级 |
|---|---|---|---|
| E1 图谱关联 | Maltego | ⭐ **不是"查得更全"，是把孤立线索连成可判断的关系网**。120+ Data Providers、12,000+ 检索方法 | Basic €0 / Entry €3,000/年 / Pro €7,500/年 |
| E2 泄露监控 | SpyCloud / IntelX / DarkOwl | ⭐ 买的是 **infostealer 日志比暗网论坛早得多**这个结构性时间差 | SpyCloud 中位 **$19,920/年**（Vendr 数据）/ DarkOwl $38,000-60,000+ |
| E3 人员情报 | Hunter / Apollo / Lusha / ZoomInfo | 找到人、找到邮箱 | ⛔ 见红线 |
| E4 ASM 平台 | Censys ASM / Palo Alto ASM | ⭐ **ASM 从外部看，映射的是攻击者能看到什么**，而不是你的内部记录声称拥有什么 | $1,750 ~ 19,999/月 |
| E5 暗网监控 | DarkOwl / Flare | 关键词命中 | Flare SMB ~$417/月 |

**Maltego 溢价的真相**：官方文档明确其 Graph 通过 120+ Data Providers 访问外部数据源，两类机制：
- **Data Pass**（官方预装打包数据，按 credit 消耗）
- **Connectors**（100+ 预置连接器，**用你自己的 API key 直连第三方**，费用你承担）

→ **€3,000/年里有相当部分是 CT 日志 + DNS 查询这类你本可以 20 行 Python 做的部分。**

**E 类合规等级：🟡 中**
- ⚠️ 采购即承担数据来源合法性责任：**Lusha 案罚款落在供应商，但合规风险同样落在不知情的采购方**
- ⛔ Maltego €3,000/年 个人自用**不值**

## F 类：灰色 / 地下渠道（Grey Channel）⛔ 红线

**这一类我列出来是为了让你知道边界在哪，不是为了让你去做。**

| 手段 | 内容 | 法律定性 |
|---|---|---|
| F1 暗网论坛监控 | 关键词监控"有没有人提到我" | ⚟️ 传统暗网监控价值可疑（"我知道有人提到我"不是可执行动作） |
| F2 stealer log | 感染机器的浏览器凭据、session cookie、钱包 | ⛔ **数据源自犯罪基础设施，持有即持有他人明文凭据** |
| F3 社工库 | `host+user+domain+password` 明文组合 | ⛔ **非公开个人信息，无任何合法性基础**。《刑法》253 条之一：**50 条以上即入刑** |
| F4 账号交易 | 被盗账号 / 撞库数据 | ⛔ |
| F5 短信/电话轰炸 | 个人信息滥用 | ⛔ |

**⭐ F 类最被低估的运维事实**：

> **stealer log 里的有效 session cookie 比密码更致命 —— 改密码无效，必须吊销会话。**
> 这是凭据暴露领域最被低估的事实，也是商业情报平台溢价的真正理由。

**F 类合规等级：⛔ 绝对禁止**（屋勘明确不做）

**F 类不作为**：**免费查询不是控制手段。** OSIntBench 评测指出：红队输入客户域 → 立刻拿到"感染机器 + 企业凭据"清单，**在委托流程正式开始之前就形成了发现**。SOC 分析师凌晨查同一个域，会发现正在追查的账户 6 个月前就被收割了。

## G 类：人工与协作（Human Intelligence）🟢 低风险但不可替代

| 手段 | 内容 |
|---|---|
| G1 钓鱼邮件 | 诱导授权确认 / 弱口令 |
| G2 电话/话术 | 套取信息 |
| G3 物理走访 | 实地勘察机房、办公环境 |
| G4 供应链询问 | 向供应商/客户询问资产归属 |
| G5 内部访谈 | 蓝队内部资产台账核对 |
| G6 情报共享 | 同行通报 / SRC / CSIRT |

**G 类是唯一"机器替代不了"的一类。** 报告原话：

> **蓝队在生产环境做全量 SYN 扫描会触发自家安全团队告警 —— 这是授权流程要解决的事，不是技术问题。**

**G 类合规等级**：🟢 低，但**必须有书面授权**。发现暴露资产**走规范披露渠道**（security.txt / 厂商 SRC / 本国 CSIRT），不要"顺手测一下"。

# 维度三：按工作阶段分（5 阶段）

**这层决定"工具该支持什么工作流"。**

```
阶段 0  情报准备          找目标 · 找入口 · 定范围
   ↓                      手段：E1 图谱 + C1 Dork + G 人工
阶段 1  建制摸底          资产全景 · 第一次全量
   ↓                      手段：B 类全开 + A 类小规模验证
阶段 2  深入探测          弱点发现 · 服务细查
   ↓                      手段：A3 A4 A5 A6 A7 + C 类
阶段 3  持续监控          变化检测 · 新增资产 · 证书到期
   ↓                      手段：基线 diff + 定时快照
阶段 4  事后溯源          事件响应 · 证据链 · 影响面评估
                          手段：G 人工 + 全部历史数据
```

**阶段划分的价值**：

| 阶段 | 核心问题 | 失败模式 |
|---|---|---|
| 0 → 1 | "我要摸的目标到底是什么" | 目标定义不清 → 范围失控 → 越权 |
| 1 | "它现在有什么" | 只做被动 → 漏"现在还开着"的资产 |
| 1 → 2 | "哪些是真正值得深入的" | 无分层 → 对 CDN 边缘节点做深入探测，浪费时间 |
| 2 | "哪里有弱点" | 只看单点 → 漏关联（悬垂 CNAME → 云上 bucket） |
| 3 | "有没有变化" | ⭐ **大多数团队死在这一步** —— 单次扫描谁都能做，基线才是复利 |
| 4 | "影响面多大" | 无证据链 → 报告不可信、结论不可辩护 |

1. ⭐ **列 1-4（资产归属 / DNS / 证书 / IP 归属）可以用纯被动手段做到 3 个星**。这四类**零法律风险、成本极低**，是工具起手就该做全的部分

# 合规风险分级

**给每个信息类型打上风险标签，工具的默认行为由风险等级决定。**

| 等级 | 含义 | 工具行为 | 涉及手段 |
|---|---|---|---|
| 🟢 **零风险** | 查公开数据，不向目标发包 | 默认开启，无需授权 | B / C / D |
| 🟡 **中风险** | 涉及个人信息或第三方采购 | 需明确声明用途 | E1 图谱 / E4 ASM |
| 🔴 **高风险** | 主动向目标发包 | **必须显式开启 + 端口白名单** | A 类全部 |
| ⛔ **红线** | 侵犯公民个人信息 / 持有他人凭据 | **永不做** | F 类全部 |

**三个必须写进代码的判断**：

| 判断 | 依据 |
|---|---|
| 检索公开索引 ≠ 使用数据 | 查 Shodan/FOFA 索引通常合法；**主动探测结果立刻改变性质** |
| **用免费层数据做正式商业交付是合规风险** | FOFA 免费/个人/专业版均不可商用 |
| **采购即担责** | Lusha 案：罚款落在供应商，但合规风险落在不知情的采购方 |

**不能当抗辩理由的**（报告原文）：
- ❌ "AI 生成的代码"
- ❌ "开源工具"
- ❌ "仅供学习"
- ❌ "只查没动手"
- ❌ "扫描被拦截了没成功"

> 已有明确案例认定：**"AI 作为工具，不改变违法行为的法律性质"**
> ⚠️ 还有**"一案双查"机制**（2018 年起全面实行）：查员工泄露数据时同步检查企业是否履行网络安全义务，**企业独立面临行政处罚**（双重处罚依据《数据安全法》第 45 条、PIPL 罚则）

# 屋勘该做哪几类

**从矩阵反推功能边界：**

| 手段大类 | 屋勘做不做 | 对应功能 | 理由 |
|---|---|---|---|
| **A 主动探测** | ✅ **做，但要授权** | ports / http / tech / paths | 核心能力，但必须在白名单约束下 |
| **B 被动索引** | ✅ **做，重点** | subdomains（crt.sh + 被动 DNS） | 零风险、高产出 |
| **C 公开检索** | ✅ 做（轻量） | 搜搜索引擎 dork | 顺手，成本低 |
| **D 注册备案** | ✅ **做，重点** | whois / RDAP / ICP 备案 | 零风险，国内资产必备 |
| **E 第三方** | 🟡 只用免费层 | IP 归属查询（ipwho.is 等） | 自己用不需要买商业情报 |
| **F 灰色** | ⛔ **永不做** | — | 法律红线，无取舍空间 |
| **G 人工** | 🟡 工具只做辅助 | 输出报告给人签字 | 机器替代不了 |

**信息类型覆盖：**

| 覆盖 | 类型 | 手段 |
|---|---|---|
| ✅ 全覆盖 | 1 资产归属、2 DNS、3 证书、4 IP 归属、11 历史 | B + C + D |
| ✅ 授权后覆盖 | 5 端口服务、6 应用指纹、7 Web 内容 | A3 A4 A5 A6 A7 |
| 🟡 部分 | 8 配置凭据泄露（仅被动查公开仓库）、9 代码仓库情报、12 业务组织 | B6 + C |
| 🟡 有限 | 13 威胁情报（免费源：abuse.ch / PhishTank / OTX） | — |
| ⛔ 不做 | 10 人员联系方式、14 暗网攻击者面 | — |

## 一句话收尾

> **信息收集不是一种活，是七种手段 × 十四类信息 × 五个阶段的组合。**
>
> 工具应该做的是：
> - **零风险的（B+C+D）全自动化，做全** ← 这是 90% 的价值
> - **高风险的（A）默认关闭，需要明确授权** ← 这是责任边界
> - **红线的（F）永不做** ← 这是底线
> - **灰色需求（E）用免费层，不花钱** ← 这是成本控制
>
> 少做一类可能够用，**漏掉"零风险那三类要做全"是最常见的浪费**。

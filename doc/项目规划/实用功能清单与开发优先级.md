## 1. 功能优先级排序（按日常使用频率 × 痛点强度）

### 🥇 P0 — 没有这些等于没有工具

| # | 功能 | 一句话 | 为什么天天用 |
|---|---|---|---|
| F1 | **IP 归属批量查询** | 丢一堆 IP 进去，出国家/城市/ASN/运营商 | 每次渗透摸到一堆 IP，第一件事就是问"这哪来的"。**重复度最高** |
| F2 | **域名信息卡** | 一个域名进去 → DNS/WHOIS/证书/子域/IP归属/备案 一次出齐 | 干活第一步。相当于"一个命令把功课做一半" |
| F3 | **子域名收集** | crt.sh + 被动 DNS + 证书 SAN 多源合并去重 | 攻击面入口，一个都不能漏 |
| F4 | **端口扫描 + 服务识别** | 并发扫、抓 banner、识别服务名和版本 | 标准动作 |
| F5 | **批量导出** | JSON / CSV / TXT，能直接喂 nuclei、httpx | 工具链要能串，不串就废 |
| F6 | **favicon hash 反查** | 给一个站点，算出 Shodan hash，查全网同款系统 | ⭐ 白嫖 Shodan 数据库的经典手法，**零成本高价值** |

### 🥈 P1 — 干活时会想起

| # | 功能 | 一句话 | 备注 |
|---|---|---|---|
| F7 | **敏感路径探测** | `.git/HEAD`、`.env`、`config.php.bak`、`admin/`、`backup.zip` 一批跑 | 渗透测试高频命中 |
| F8 | **指纹识别** | Server 头 / Cookie / 特定路径 / 正文关键词 → 框架和版本 | 别信 Wappalyzer 一家 |
| F9 | **证书 SAN 提取** | 证书里的所有域名 = 潜在攻击面 | 顺手做，成本极低 |
| F10 | **页面截图存档** | 每个 URL 截一张图，存到 `.work/shots/` | 交报告、写记录要用 |

| F12 | **历史 URL 挖掘** | gau / wayback 拉历史链接 | ⚠️ 验证存活需授权，默认只列不探 |

## 2. 核心命令面（按实际使用流程设计）

```bash
# ============ 最高频：IP 归属批量查 ============
wukan ipinfo 1.1.1.1 8.8.8.8 93.184.216.34
wukan ipinfo -f ip.txt                          # 从文件读
wukan ipinfo -f ip.txt -o ip.csv                # 出表格
# 输出：IP | 国家 | 城市 | ISP | ASN | 组织 | 是否云厂商 | 是否CDN

# ============ 第二高频：一句话摸清一个域 ============
wukan recon example.com
# 一次输出全齐：
#   ├─ DNS：A / AAAA / NS / MX / TXT / CNAME
#   ├─ WHOIS：注册商 / 注册人 / 创建时间 / 过期时间
#   ├─ 证书：签发者 / SAN 全部域名 / 到期天数
#   ├─ 子域：多源合并去重列表
#   ├─ IP：每个 IP 的归属信息
#   └─ 备案：ICP 备案号（国内域名）

# ============ 分步执行（精细控制时）============
wukan subdomains example.com              # 只收子域
wukan dns example.com                     # 只解 DNS
wukan cert example.com:443                # 只扒证书
wukan ports -f hosts.txt --ports top100  # 扫端口
wukan http -f urls.txt --probe           # 探 HTTP
wukan tech  -f urls.txt                  # 识别技术栈
wukan paths -f urls.txt --profile web    # 敏感路径探测
wukan favicon https://example.com --shodan   # favicon 反查

# ============ 导出（工具链要能串）============
wukan recon example.com -o recon.json
wukan recon example.com -o recon.csv
wukan recon example.com --urls-only -o urls.txt | httpx -l -

# ============ 辅助 ============
wukan page  -f urls.txt --shot           # 批量截图
wukan sites -f urls.txt --sitemap         # 解析 sitemap
wukan hist  example.com                   # 历史 URL（只列不探）
wukan report -o report.md                 # 把结果拼成报告
```

### 设计原则

| 原则 | 说明 |
|---|---|
| **一个命令出一份全结果** | `recon` 是主力命令，剩下都是可以单独调用的零件 |
| **所有输入支持 `-f`，所有输出支持 `-o`** | 能进能出，才能串进现有工具链 |
| **默认不探、只列** | 涉及主动探测的默认关，要加 `--probe` 才开 |
| **输出默认给人看（表格），`-o` 给机器读** | 两种受众都得伺候 |

## 3. 技术选型（砍到最简）

| 项 | 选型 | 说明 |
|---|---|---|
| 语言 | **Go** | 单 exe、内存低、并发扫描天然适配 |
| CLI | `spf13/cobra` | PD 套件同款 |
| HTTP | 标准库 `net/http` | 不引第三方，减少依赖 |
| DNS | `github.com/miekg/dns` | 纯 Go |
| SQLite | 可选 | 只有做快照 Diff 才需要，P0 不引 |
| 并发 | `golang.org/x/sync/semaphore` | 限流 |

**依赖总数目标：≤ 5 个**。个人项目最怕依赖树腐烂。

### ⚠️ 依赖避坑（照旧，这条会真咬人）

| 禁止 | 原因 |
|---|---|
| `nmap` | NPSL 禁止嵌入；仅"读 nmap-service-probes"就构成衍生作品 |
| `masscan` / `TruffleHog` | AGPL-3.0 |
| `waybackurls` | **无 LICENSE = 保留所有权利** |
| `mattn/go-sqlite3` | CGO + SQLite 许可争议 |
| `maltego` | €3,000/年起，个人自用不值 |

## 4. 安全边界（简化版，20 行搞定）

**不搞复杂系统，但保留最基本的护栏。**

```jsonc
// wukan.json（放项目根目录，可选）
{
  "probing": {
    "allowed_ports": [80, 443, 8080, 8443],   // 白名单，禁止 -p-
    "rate_limit": 10,                          // pps 上限
    "time_window": "09:00-18:00"
  }
}
```

规则就三条：

1. **默认不探**。`wukan recon example.com` 只做被动，主动要显式 `--probe`
2. **主动探测时端口必须在白名单里**。`--ports -` 或 `top100` 在开启探测时直接报错
3. **README 第一节写明不做什么**（SMTP 枚举 / 人员情报 / 暗网 / 漏洞利用 / 全网扫描）

> 为什么不做 v1.0 那套完整授权台账：**你给自己用，复杂授权系统反而是负担**。留个白名单防手滑就够了。法律风险靠"只扫你有权扫的"这个自觉 + 白名单约束，成本最低。

## 6. 明确不做的

| 不做 | 原因 |
|---|---|
| SMTP 邮箱枚举 | 法律风险收益比极差 |
| 人员情报 / 社工库 | ICP 253 条 50 条入刑，PIPL 更严 |
| 暗网 / stealer log | 持有即持有他人明文凭据 |
| 漏洞利用 | 跨过"信息收集"的量级 |
| 全网扫描 | 董某案：扫描本身即被认定为"侵入"的实施行为 |
| AI 指纹识别 | 报告已查证：不存在可信基准，httpx 本身就是规则匹配 |
| 套壳式流水线 | `subfinder \| naabu \| httpx` 你自己就能写，30 行搞定 |
